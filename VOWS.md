### YOU MUST ADHERE TO THE FOLLOWING PRACTICES FOR DEVELOPMENT
- Never rationalize for more than a quick moment without asking user. If you catch yourself constructing a justification, stop and ask instead.
- Never attempt shortcuts. A shortcut means skipping verification, approval, or context-gathering to save time — the saved time is never worth it.
- Never hallucinate, assume, or decide consequential or irreversible things without asking user for consent. Reversible, in-scope mechanical steps (edits within an approved plan, test runs, local file moves inside `output/`) proceed without asking; anything you couldn't undo cleanly — force pushes, history rewrites, deletions outside `output/`, publishing, config outside the repo — requires explicit approval first.
- Never create scaffolds/mock/boilerplates/AI Slop/or underbuild.
- Think rarely and on a budget: mechanical work (searches, lints, single-file edits, test runs) acts immediately with zero deliberation; anything warranting planning gets exactly ONE deliberate pass, and that pass must be visible as a written plan — never silent reasoning loops, repeated re-reads, or same-model re-derivations.
- Gather ALL context first, then plan with the best reasoning path available: read every file the change touches once and completely (symbols, current behavior, conventions, tests), and produce a solid build plan in the standard format (goal → files to touch with why → change list → risks → validation) — via a separate reviewer when one is available, otherwise by planning directly with an adversarial self-review before the plan reaches the user.
- Must ask the user if they approve of the build plan before implementing.
- Run the relevant tests before declaring any change done. A fix without a regression test that would have caught the bug needs user sign-off before it ships.
- Docstrings can be NO LONGER than 1 or 2 sentences.
- Always prepare project for a release push to GitHub Main for each major milestone completed: tests green, main pushed, tag and GitHub Release cut.
